# 问题记录

本文记录编码过程中发现但未完全闭环的问题、风险和后续处理建议。

## 2026-05-17

| 编号 | 模块 | 问题 | 影响 | 状态 | 建议 |
|---|---|---|---|---|---|
| ISSUE-001 | 项目仓库连接测试 | Gitee HTTPS Token 在不同组织/仓库权限策略下可能要求不同认证格式。当前实现使用 `oauth2:<token>` 注入 HTTPS URL 进行 `git ls-remote` 测试。 | 如果目标 Gitee 实例不接受该格式，连接测试会失败，但不代表仓库一定不可访问。 | 已记录 | 后续用真实目标仓库和令牌验证；必要时增加认证模式配置。 |
| ISSUE-002 | Excel 导入 | 当前后端支持 `.xlsx` 工作簿导入，未支持老式 `.xls`。 | 用户上传 `.xls` 会导入失败。 | 已记录 | 如有兼容需求，增加 `HSSFWorkbook` 分支或统一要求模板为 `.xlsx`。 |
| ISSUE-003 | 项目仓库连接测试 | 首版 Git 探测先读取进程输出再等待退出，网络不可达时会导致接口等待过长。 | 仓库连接失败路径响应不及时。 | 已修复 | 已改为先按超时时间等待进程结束，超时后强制终止，再读取输出。 |
| ISSUE-004 | AI 生成脚本 | `/api/rule/generate-script` 依赖 DeepSeek 配置与调用客户端，当前尚未完成 AI 客户端模块。 | 该接口暂时不能生成真实脚本。 | 已记录 | 完成 DeepSeek 配置、加密存储、Function Calling 客户端后再启用。 |
| ISSUE-005 | 脚本规则测试运行 | 当前支持脚本测试运行和超时终止，但还没有生产级沙箱隔离。 | 恶意脚本可能访问本机资源。 | 已记录 | 后续引入容器隔离、工作目录限制、环境变量白名单和输出大小限制。 |
| ISSUE-006 | 检视任务引擎 | 当前 `/api/review-task/manual-start` 只创建 `PENDING` 任务，尚未接入异步执行器、Git diff、AI Function Calling 和问题落库链路。 | 手动发起后不会真正执行代码检视。 | 已记录 | 下一阶段实现 ReviewEngineAppService、GitDiffService、DeepSeekClient、AiResponseParser，并接入异步线程池。 |
| ISSUE-007 | 看板统计 | 当前看板统计基于现有任务/问题表做基础聚合，尚未做时间范围参数、缓存和复杂排行名称补全。 | 数据量大时性能和展示细节不足。 | 已记录 | 后续增加统计查询参数、SQL 聚合优化和项目名称补全。 |
| ISSUE-008 | Notify module | Notify config, template CRUD, preview, and Webhook test-send APIs are available, but task success/failure does not trigger automatic notification yet. | Review tasks still need manual API calls to send notification test messages. | Recorded | Wire NotificationAppService into the review engine success/failure flow and select enabled templates by event type. |
| ISSUE-009 | Notify security | Webhook Secret is currently stored in `secret_encrypt` without real encryption, although API responses return a masked value. | Database operators can still see Secret plaintext, which is not production-ready. | Recorded | Add SecretEncryptor with environment-provided master key, encrypt on save, decrypt only when sending Webhook. |
| ISSUE-010 | Review engine | The review engine now supports async task execution, Git clone/pull/diff, script rule execution, issue persistence, and task statistics, but DeepSeek Function Calling and advanced diff chunking are not implemented yet. | AI rules are still not executed during review tasks; large diff handling is currently capped instead of chunked by file/hunk. | Recorded | Add DiffChunk model, AI request builder, DeepSeek client, function-call parser, and per-rule retry/error isolation. |
| ISSUE-011 | AI review engine | DeepSeek Function Calling client, AI rule execution, and basic file/size diff chunking have been wired into the review engine, but they have not been verified with a real DeepSeek API Key and live model response in this environment. | AI rule behavior still needs real external API validation; prompt/schema compatibility problems may surface during live testing. | Recorded | Configure `CODE_REVIEW_DEEPSEEK_API_KEY`, run an AI rule against a small real repository, and tune prompt/template/schema mapping based on the returned function arguments. |
| ISSUE-012 | Diff chunking | Current diff chunking splits by file diff and max character length, not by semantic hunk boundaries with line metadata. | Very large files can be split in the middle of a hunk, and AI issue line positioning may be less accurate. | Recorded | Add hunk-level parser carrying old/new start lines, file path, and chunk sequence metadata. |
| ISSUE-013 | Runtime baseline | The project build and design docs have been updated from JDK 8 to JDK 17. | Local and packaged runtime are now aligned with the actual JDK 17 environment. | Fixed | Keep deployment scripts and CI runners on JDK 17. |
| ISSUE-014 | DeepSeek config security | DeepSeek API Key can now be configured through `/api/system-config/deepseek/update`, but it is stored as plaintext in `cr_system_config`. | This is convenient for MVP validation but not production-ready. | Recorded | Reuse the planned SecretEncryptor to encrypt DeepSeek API Key before production deployment. |
